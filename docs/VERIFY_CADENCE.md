# 验证节奏与阶段审核（唯一权威出处）

> 本文规定**何时跑哪一层验证**。验证链本身的内容（verify 四步、补丁、护栏）见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 5 节；为什么这么定见 [DECISIONS.md](DECISIONS.md) ADR-009。
> 原则：小项目不做大项目的仪式。本机零成本验证全量跑，模拟器验证按风险分层、集中在阶段末，全项目审阅按里程碑触发。

## 1. 验证分层

| 层 | 手段 | 成本 | 覆盖什么 | 抓不到什么 |
| --- | --- | --- | --- | --- |
| T0 静态全量 | `npm run verify`（doctor + typecheck + node 测试 + 静态护栏） | 本机秒级，零 token | 类型错误、规则逻辑错、三层边界违规、Map/Set 展开违规 | 构建错译、真机运行时行为、跨场景流程 |
| T1 定向回归 | 模拟器内验证单个流程模块 | 一次 flash 会话 20~40 次调用 | 被改流程的行为 + 相邻存档读写 | 其他模块 |
| T2 冒烟 | 构建产物能起、主流程能走通 | 一次 flash 会话 ~10 次调用 | 白屏、启动崩溃、主流程断裂 | 模块内行为细节 |
| T3 全量回归 | 全部流程模块走一遍（F1~F6） | 一次 flash 会话 100+ 次调用 | 构建错译、跨场景流程、存档全链路 | —（最后一道闸） |
| 全项目审阅 | 一次会话通读全部代码+文档+测试 | 短 glm-5.3 会话 | 语义/逻辑/架构/文档一致性（ADR-008 类问题） | 构建错译、运行时行为 |

## 2. 触发规则

**日常切片（默认）：只跑 T0。** 切片完成 → `npm run verify` 全绿 → 提交。不开模拟器、不跑回归、不做全项目审阅。切片卡上写明「本切片只跑 T0」。

**T1 定向回归**——改动落在某个流程模块内部、且该改动触及**存档读写或行为分支**时，本切片加跑所涉模块：

- 例：改 `resolveEvent` 结算逻辑 → 只跑 F2 道路事件 + 相邻存档恢复。
- 例：改 `advanceDay` → 只跑 F5 十日循环/结局/清档。

**T2 冒烟**——表现层/平台层改动且不触及规则语义（布局、文案、纯演出）：

- 例：改按钮位置、调 Tween 参数、改面板文案。
- 构建通过 + 能起 + 主流程走通即可。

**T3 全量回归 + 全项目审阅**——只在阶段收官（每 2~3 个切片或一个里程碑）或全局风险改动时：

| 触发 | 说明 |
| --- | --- |
| 阶段收官 | 一个阶段的切片全部完成、骨架闭环时 |
| 构建管线改动 | `tools/patch-wechat-deprecated.mjs`、Cocos 版本、构建配置 |
| 存档结构变更 | `save.v1` 等任一存档键的 schema 变化（键位登记见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 3 节） |
| 静态护栏自身改动 | `tools/verify-project.mjs` 的断言规则变化 |
| 发版前 | 对外发布版本之前 |

全局风险改动即使 diff 只有一行也触发 T3——护栏/补丁/构建配置的爆炸半径是整个包（ADR-006 反例）。

**全项目审阅的适用规模**：当前 3000 行级一次会话可审完（ADR-008 实证）。当业务代码超 ~8000 行或单文件超 ~500 行时，改为按层/按模块分次审阅。

## 3. 流程模块划分（T1/T3 的范围单位）

按**玩家可见流程**切分，不按代码目录切分。每个模块 = 注入存档 → 操作序列 → CDP 断言。模块间不互相依赖，入场状态由存档注入控制。

| 模块 | 玩家流程 | 主要代码 |
| --- | --- | --- |
| F1 出发行程 | 地图选点、扣油弹、行车卷轴 | `route.ts`、`TravelScene` 行车段 |
| F2 道路事件 | 事件弹出、选择、后果结算 | `sim.resolveEvent`、`game.ts` 事件表 |
| F3 节点搜刮 | 节点抵达、候选物资、装舱 | `loot.ts` |
| F4 抵仓入库 | 返程抵仓、物资折算入库 | `sim.returnHome`、`cargoFromTrunk` |
| F5 十日循环 | 推进天数、结局触发、重开清档 | `sim.advanceDay`、`PrototypeScene` 清档 |
| F6 货舱整理 | 货舱网格操作、堆叠移动 | `trunk.ts`、`TrunkGrid` |

## 4. 阶段审核怎么做

阶段末由 glm-5.3 会话（架构师）执行，两件事一次做完：

1. **全项目审阅**：通读 core/presentation/platform + tests + docs，检查维度沿用 ADR-008：文档承诺与实际执行一致、玩家视角复述语义与实现一致、护栏断言范围与承诺一致、存档键位登记完备、死代码与半成品状态。
2. **T3 全量回归**：产出回归任务卡（见第 5 节），由 glm-5.3-flash 顶层会话执行（模拟器驱动需要 computer-use/图像能力，flash 有、glm-5.3 无图像输入；子代理无 computer-use，必须顶层会话）。

审阅发现的问题**集中修复**后，重跑受影响层级的验证再提交。

## 4b. 角色与会话纪律（架构师/执行工分工）

- **架构师（glm-5.3）**：切片规划、任务卡、评审、提交信息、git 提交。短会话。
- **执行工（glm-5.3-flash 等低倍率模型）**：切片实现、构建、T1~T3 回归。**新开顶层会话**（子代理继承会话模型且无 computer-use，不能由 glm-5.3 会话派出）。
- **一切片一会话**：执行会话只回传结论（PASS/FAIL + 证据），不回传过程；完成即收口，提交权在架构师。
- **执行会话调用数逼近 100 或上下文过 15 万 token 即强制收口重开**（会话成本 O(N²) 增长，实测拐点）。
- 模型能力约束：glm-5.3 无图像输入；截图判断/模拟器目测必须路由给 flash / doubao / kimi（支持图像的模型）。

## 5. 任务卡规范

T1~T3 回归与执行切片共用任务卡格式，落在 `docs/tasks/`（目录不存在则建）：

```markdown
# <REGRESSION_F?_日期> 或 <SLICE_00X_主题>
## 范围
（改了什么 → 验什么；引用本文档的模块编号与层级）
## 环境
（项目根、竖屏 750×1334、CDP 9222、构建/开模拟器命令；写明"已就绪"或"需自行构建"）
## 工具纪律
- CDP 断言优先（node tools/cdp-eval.mjs '<expr>'，项目根执行）
- 仅验证真实触摸路径时用 computer-use 点击；截图仅用于定坐标，不做整屏目测
## 清单
（每条 = 操作 → 断言表达式 → 期望值）
## 汇报格式
PASS/FAIL + 证据 + 意外发现；不改代码、不 git 提交；结果写回本卡「结果」栏
## 结果
（执行会话填写）
```

## 6. 与既有规则的关系

- 本文档**不改变** [ARCHITECTURE.md](ARCHITECTURE.md) 第 5 节验证链的内容，只规定**何时跑**。
- README「切片进度」的「每个切片独立可运行、只验证一个问题」继续有效：前者指交付形态，后者指验证焦点；本文档规定**验证频率**。
- `.agents/skills/wasteland-depot-dev/SKILL.md` 的「表现层改动必须构建 Web 验证」自本文档生效起**废止**，改为按本文档分层触发。
- ADR-006/007 的教训不变：tsc 查类型不查行为、构建错译只有模拟器能抓；因此触及存档/行为分支的改动至少 T1，全局风险必 T3。
