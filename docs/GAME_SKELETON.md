# 《末班车：废土仓库》游戏骨架

> 状态：首版共同模型。本文整理自立项讨论，用来约束原型、切片和后续需求；它描述的是游戏，不等同于当前已实现功能。

## 1. 一句话定义

玩家驾驶一辆末班车，以废弃仓库为据点，在有限油料、弹药和车辆载重下外出探索；每次都要在物资与幸存者之间做取舍，再用带回的成果维持据点并扩大下一次探索范围。

第一版不是大型基地建设游戏，而是：

> 一辆车、一个仓库、六个地点组成的十日微型生存循环。

## 2. 核心体验

游戏最重要的问题不是“能打赢多少敌人”，而是：

> 后备箱已经装满，但前方出现了更需要的东西，我要留下什么、丢掉什么？

资源、伤员和幸存者都竞争有限空间。玩家的选择会影响本次外出的收益、据点的长期生存，以及后续可走的路线。

典型抉择：车辆只能再装一件东西时，是保留三个药箱，还是腾出空间救下一名可能成为医生的幸存者。

## 3. 核心循环

单次外出目标时长约 3 分钟：

```text
查看据点状态与地图
        ↓
选择目的地和同行者
        ↓
消耗燃油与弹药出发
        ↓
处理道路事件、拾取物资或救助幸存者
        ↓
在有限载重中持续取舍
        ↓
抵达地点，完成一次高价值选择
        ↓
返回仓库，分配资源、治疗、维修与升级
        ↓
推进一天，世界危险度上升
```

十日构成一局完整流程。玩家要在不断恶化的环境中达成最终目标，并根据途中选择进入不同结局。

## 4. 第一版内容边界

| 维度 | 首版规模 |
| --- | --- |
| 地图 | 1 片区域，以仓库为中心 |
| 探索地点 | 6 个 |
| 仓库设施 | 4 个 |
| 资源 | 5 种 |
| 幸存者职业 | 4 种 |
| 车辆 | 1 辆 |
| 流程 | 10 个游戏日 |
| 随机事件 | 20～30 个 |
| 最终目标 | 1 个 |
| 结局 | 2～3 种 |

这些数字是首版范围上限，不是要求一次性全部实现。每个开发切片仍要独立可运行、只验证一个问题。

## 5. 五种资源

| 资源 | 主要用途 | 形成的压力 |
| --- | --- | --- |
| 燃油 | 决定可到达地点和返程余量 | 探索半径与安全余量的取舍 |
| 食物 | 维持幸存者日常消耗 | 人口增长会提高持续成本 |
| 材料 | 修复和升级仓库、车辆 | 当前生存与长期投资的取舍 |
| 药品 | 治疗伤员和疾病 | 是否为未来风险保留稀缺资源 |
| 弹药 | 处理危险事件 | 战斗不是免费收益，而是资源交换 |

首版不增加货币、木材、矿石等平行资源；确有玩法必要时，先证明现有五种资源无法表达该选择。

## 6. 四处仓库设施

| 设施 | 作用 |
| --- | --- |
| 仓储间 | 提高资源存储上限 |
| 维修间 | 修复车辆并进行车辆升级 |
| 医务室 | 治疗伤员，降低伤病带来的损耗 |
| 无线电台 | 发现新地点、幸存者和路线情报 |

设施只做少量等级和清晰数值，不发展成自由摆放、生产链或复杂建筑树。

## 7. 车辆与后备箱

车辆只保留四项能力：

- 载重：决定后备箱格数或可承载体积。
- 油耗：影响每次外出的燃油成本。
- 防护：降低危险事件造成的损失。
- 探索距离：解锁更远的地点和路线。

后备箱是核心交互界面。物品以格子或形状占用空间；幸存者、伤员也会占用载重。拖拽只是表现手段，真正要验证的是取舍是否清楚、有压力且不繁琐。正式交互方向见 [INVENTORY_DESIGN.md](INVENTORY_DESIGN.md)。

## 8. 幸存者

幸存者不做装备栏、复杂属性和技能树。每人先只有一个职业特点：

| 职业 | 首版特点 |
| --- | --- |
| 司机 | 降低外出油耗 |
| 机械师 | 降低维修或车辆升级消耗 |
| 医生 | 降低治疗所需药品 |
| 侦察员 | 提前显示部分道路危险或资源情报 |

职业作用必须改变玩家的选择，不能只是小幅百分比堆叠。具体数值在规则原型中验证后再定。

## 9. 地点与事件

六个地点应各自提供不同的资源预期与风险，而不是只换背景。立项讨论中出现过的候选地点包括兵工厂、医院、河边和牧场；剩余地点及最终组合尚未确认。

事件采用“信息 → 选择 → 即时或延迟后果”的小型结构，优先复用规则组合，而不是依赖大量一次性剧情。事件至少应影响以下一项：

- 后备箱空间。
- 五种资源。
- 车辆状态。
- 幸存者状态或职业组合。
- 路线情报和后续地点。
- 最终结局条件。

首版战斗只作为事件结算，不开发实时战斗、寻路或战斗 AI。

## 10. 序幕与首局教学

序幕控制在约 15 秒内开始操作：

1. 车辆自动驶向废弃仓库。
2. 公路上出现燃油、食物、材料和少量幸存者。
3. 车辆无法装下全部对象。
4. 玩家完成第一次放弃物资或放弃救人的选择。
5. 抵达仓库，刚才带回的内容直接成为开局资源。

序幕同时承担世界观、操作教学和第一次核心取舍，不制作长过场。

## 11. 广告与付费底线

广告只能提供额外选择，不能消灭载重和生存取舍。

- 不放横幅、开屏和强制插屏。
- 只允许玩家主动触发的低频激励视频。
- 广告失败或拒绝观看不阻断正常游戏。
- 不用“全物资翻倍”破坏核心规则。
- 不通过提高油耗、制造必死局等方式贩卖解药。

首版候选入口只有无线电侦察和事故后的紧急救援；是否保留、频率和代价都要在完整核心循环成立后再验证。付费和 PC 买断版不属于首版范围。

## 12. 当前技术探路版在验证什么

现有三格后备箱原型不是完整游戏，它只验证：

- Cocos 竖屏触摸与拖拽是否可靠。
- 物资进入、移出和替换槽位的规则是否可测试。
- Web 与微信环境是否能使用同一份规则和不同存储适配。
- Cocos 构建、微信开发者工具和真机链路是否畅通。

探路版通过后，下一个可玩切片才引入“一次短途外出中的连续载重取舍”，并把三格探针替换为候选物资区与车辆货舱；暂不加入基地建设、战斗和广告。

## 13. 尚未确认

以下内容不能在实现时自行补全，进入开发前需由财哥和丧彪共同确认：

- 十日最终目标和明确的胜负条件。
- 六个地点的最终名单、路线结构与资源倾向。
- 物资采用单格、不同尺寸，还是重量与格子混合规则。
- 幸存者是否直接占后备箱空间，以及伤员的特殊规则。
- 世界危险度的具体表现和增长方式。
- 2～3 种结局的触发条件。
- 美术风格、叙事尺度和审核安全边界。

## 14. 停车场：首版明确不做

- PC 版及跨平台界面。
- 开放世界或多区域大地图。
- 实时战斗、寻路和敌人 AI。
- 自由建造、复杂生产链和建筑摆放。
- 角色装备、技能树和多人关系模拟。
- 多车辆编队。
- 联机、排行榜和社交系统。
- 物理引擎、3D、骨骼动画和重型粒子效果。
- 付费系统及广告变现调优。

新想法先记录在停车场；只有当前切片通过人工验证，才讨论是否移入正式范围。
