# SLICE_002：4×3 货舱交互

> 状态：自动验证 ✅ 通过（规则测试 + Web 浏览器验证）；人工验收 ⏳ 待财哥在**微信小游戏端**确认手感。
> 设计依据见 [INVENTORY_DESIGN.md](INVENTORY_DESIGN.md)。完成本切片前，不把货舱交互视为定稿。

## 验证的问题

一次连续装车取舍是否成立：4×3 货舱 + 不同尺寸物资，点选放置为主、拖拽为辅，配合高亮/吸附/失败提示，能否让「装不下全部」的取舍清楚、有压力且不繁琐。

## 范围（只做这些）

- 规则层 `core/trunk.ts`：4 列 × 3 行共 12 格；物品按 1×1（食物/药品/弹药，可堆叠）、2×1（燃油/材料）、2×2（幸存者/伤员，规则预留）占格；放置/移动/交换/堆叠/移除全部纯函数。
- 界面：候选物资区（食物/药品/燃油/材料/弹药 5 张卡）+ 车辆货舱 + 「清空货舱」；显示「已用 N / 12 格」。
- 交互：点选物品 → 合法格高亮 → 点格放置；拖拽作为快捷方式；两者走同一条 `placeItem` 命令。
- 反馈：选中抬起、合法格呼吸高亮、放置吸附回弹、失败格闪烁并提示原因。
- 存档：货舱布局保存/恢复（`wasteland-depot.trunk.v1`）。

## 不做（明确排除）

地图、战斗、基地建设、广告、物品旋转、重量系统、幸存者实际入舱（规则预留 2×2）。

## 实现文件

- 规则：`core/trunk.ts`（占格/堆叠/移动 + 存档编解码）。
- 表现：`PrototypeScene.ts`（货舱界面；网格渲染后在 SLICE_004 抽为 `TrunkGrid.ts`）。

## 验证结果

- 规则测试：47/47 通过（trunk 12 用例 + 既有规则）。
- Web 浏览器端交互验证通过；规则层依赖边界、引擎模块裁剪校验通过。
- 微信小游戏端交互**尚未人工确认**。

### 0. 前置：开启服务端口（一次性）

CLI 自动化依赖服务端口：微信开发者工具 →「设置」→「安全设置」→ 打开「服务端口」。

### 1. 打开项目

```bash
npm run build:wechat   # 重新构建微信版（已含兼容补丁）
npm run wechat:open    # 在开发者工具中打开 build/wechatgame
```

工具界面确认：左上角「小游戏模式」，模拟器为竖屏 iPhone。

### 2. 编译运行（快捷键 Cmd+B）

预期首屏：标题「末班车：废土仓库」、副标题「货舱 · 点选物资再点格子放置」、中部 4×3 共 12 格货舱（顶部「已用 N / 12 格」）、下方 5 张候选卡、底部「清空货舱」。

### 3. 测试步骤

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 看首屏 | 标题、12 格、5 张卡、清空按钮完整可见，无遮挡裁切 |
| 2 | 点「食物」候选卡 | 卡被选中（状态栏「已选择：食物」），可放空格变绿高亮 |
| 3 | 点第一个空格 | 食物入格，提示「已保存」，高亮消失 |
| 4 | 依次放「燃油」「材料」 | 各占 2×1 两格，布局正确，容量计数更新 |
| 5 | 放满后点已占用格 | 失败：该格闪红，提示「该位置被占用或空间不足」，不覆盖 |
| 6 | 点「清空货舱」 | 12 格全空，回到「已用 0 / 12 格」 |
| 7 | 随意摆放后重新编译/重开模拟器 | 布局从存档恢复（`trunk.v1`） |
| 8 | 切换 ≥2 种竖屏设备（iPhone 12 / SE） | 标题、货舱、候选卡、按钮、状态文字无裁切重叠 |
| 9 | 打开调试器控制台 | 无**红色错误**；黄色兼容性提示另行记录 |

### 4. 控制台 Errors / Warnings 怎么判读

调试器面板的错误计数可能来自工具/扩展自身。判断：错误文本含 `wechatgame/assets/...`、`PrototypeScene`、`trunk` 等**我们的代码**才是游戏问题；GitLens、`source`、网络、`miniprogram` 之类与游戏无关。特别关注 `Uncaught TypeError`、`Cannot read properties of undefined`、`is not a function`。CDP 回归的噪音口径见 `.agents/skills/wechat-devtools/SKILL.md`。

### 5. 反馈格式

记录：设备/模拟器型号、未通过步骤编号、实际表现（文字或截图）、红色错误截图（如有）。
