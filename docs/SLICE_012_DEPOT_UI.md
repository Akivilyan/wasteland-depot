## 冒烟抓到的真 bug

`showToast` 对陈旧 toast 引用直接读 `label.node.isValid`——旧 Toast 随 `newScreen` 销毁跨帧后 `label.node` 被置 null → TypeError。真实流程「第一次弹层操作出 toast → 第二次弹层操作」100% 复现。已修（判空链）。这是 applyInLayer 新路径首次把「弹层操作 → buildDepot 重建 → 再 toast」串起来才暴露的。

## 冒烟方法注记（给下个切片）

- emit TOUCH_END / 假 EventTouch 均无法触发 Cocos 3.8 触摸监听（引擎内部条件派发）——面板操作链用 `comp.applyInLayer` 直调 + 面板用 `comp.buildXxxLayer()` 直调，即 SLICE_009/010 既定口径。
- CDP evaluate 同步连调多次 buildDepot 时，destroy 延迟帧末导致 `getChildByName` 命中将死旧节点——断言取同名节点须 `filter(...).pop()`（真实帧流程无此现象）。
- computer-use 系统点击在本机未能驱动模拟器（帧绑定过期/激活/坐标假设均试过无效）；红块两点校准法（游戏内画标记 + 像素扫描）本身有效，坐标映射已留档：栅格 = (999.7 + dx×0.4055, 165.9 + (620−dy)×0.4056)。
