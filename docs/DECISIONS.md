## ADR-001：引擎与技术形态 —— 留在 Cocos 2D，纯 2D 竖屏单机

- 状态：已确认（2026-09-02 复评维持）
- **决定**：首版用 Cocos Creator 3.8.8 做纯 2D、竖屏、单机微信小游戏；保留 `Animation`/`Tween` 做轻量反馈，关闭 Spine、DragonBones、Box2D、音视频等未用模块；不引入 3D、物理引擎、骨骼动画、联网或第三方运行时。代码按 规则 / 表现 / 平台 三层隔离（边界与强制方式见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 1 节）。
- **理由**：游戏真实形态是「横轴旅途 + 场景变化」的归家异途变种，正是 2D 引擎价值区。曾一度判断「原生 canvas 更好」，复评后认定那只在「纯静态 UI」假设下成立，已推翻。
- **备选**：微信原生（规则层零成本可迁，引擎彻底摆烂时启用）。**排除**：团结引擎（3D/重度方案，C# 重写成本不值）。
- **教训**：评估技术方案要以完整游戏形态为准，不能用当前已实现的小切片当依据。

## ADR-002：微信新运行时兼容 —— 构建后自动打补丁兜底

- 状态：已确认（2026-09-02）
- **背景**：2026-09-02 起微信开发者工具模拟器运行时灰度更新，不再预置 `window`/`global`/`requestAnimationFrame`，`GameGlobal` 部分属性 getter-only。Cocos 3.8.8 生成的小游戏模板硬依赖这些全局，启动链逐层崩溃白屏。配置文件（project.config.json / game.json / libVersion / enhance）差异均非原因——**纯代码依赖，改配置修不了**。
- **对照实验**：开发者工具原生「小游戏 + 纯 gl 模式」模板在同一模拟器 0 错误运行；Cocos 产物必白屏。社区普遍反馈「新版运行时 window 不再注入」，微信与 Cocos 当时均无官方公告/适配。
- **决定**：`tools/patch-wechat-deprecated.mjs` 七个幂等补丁随 `npm run build:wechat` 自动执行（废弃 API shim、global/window 别名、DPR 容错、首屏 window/rAF 兜底、adapter 双分支守卫、DOMParser 暴露 globalThis）。Cocos 官方适配后即可移除。
- **开发期建议**：开发者工具「设置 → 本地设置」锁定调试基础库版本，避免灰度运行时反复横跳。

## ADR-003：旅途表现 —— 地图骨架 + 卷轴演出折中

- 状态：已确认，用户拍板（2026-09-02）
- **决定**：2D 地图做策略层（选路线/节点、开迷雾、节点状态）；点出发切横轴行车卷轴做表现层（车移动、背景滚动、随里程触发节点事件）；到节点弹出事件/搜集/货舱界面（复用现有 UI）。首版只做一条路线 + 3~5 个节点验证手感。
- **理由 / 对标**：归家异途（Home Behind）——路上横卷、地图/营地静态界面。旅途表现（车动景变）是这个游戏的「脸」，纯静态地图撑不起体验；完整开放世界又超出首版范围，折中方案用最小成本验证手感，横轴素材日后按节点对复用、不白做。

## ADR-004：复用官方能力优先，只自写官方没有的玩法规则

- 状态：已确认（立项原则）
- **决定**：开发新能力前先查官方文档（Cocos 手册 / 微信小游戏文档）；官方/Cocos/微信已提供的（存储、广告、分享、登录、开放数据域、UI 布局组件、Tween/Animation、触摸事件）只写适配层，不重写；确认官方没有的才在规则层自写，且不得依赖 `cc`/`wx`。具体「直接用 vs 必须自写」清单见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 4 节。
- **理由**：小程序包体积与维护成本敏感；自写部分集中在确定性、可测的玩法规则（货舱占格、十日循环、可种子随机、战利品抽取），这些官方确实没有。

## ADR-005：环境/兼容类异常先联网检索，对照实验用官方模板

- 状态：已确认，用户反馈确立（2026-09-02）
- **决定**：遇到环境/工具链类异常（非自己代码逻辑错误），先联网检索是否社区普遍现象、有无官方公告（WebFetch 超时国内站点时用 `arkcli +chat --tools web_search`），再决定跟官方方案还是自己兜底，不顺着调用栈埋头深挖。做兼容性对照实验时，用官方向导/官方模板新建项目，不手工拼 `project.config.json`（会被 GUI 覆盖模式字段）。
- **理由**：ADR-002 的白屏问题正是靠「先查社区 + 官方模板对照」快速定位为运行时变更，而非逐行追 Cocos 启动链。

## ADR-006：核心层禁用 Map/Set 展开语法 —— 微信构建会静默错译

- 状态：已确认（2026-09-03，SLICE_005 回归实证）
- **背景**：SLICE_005 微信模拟器回归发现「抵仓入库」把材料折算成 `undefined`（日志「带回 NaN 格物资」）。规则层 Node 测试全绿，只有构建产物行为错误。反编译 `build/wechatgame/assets/main/index.js` 实锤：Cocos 的 TS 降级编译把 `[...someMap]` 编成 `[].concat(someMap)`——`concat` 不展开 Map，得到 `[Map]` 而非条目数组；解构后字段全为 `undefined`。
- **决定**：`assets/scripts` 内禁止对 Map/Set（及 `.keys()/.values()/.entries()` 迭代器）使用数组展开；遍历用 `forEach`，收集用普通循环 push。数组与对象字面量展开不受影响（编译为 `concat`/`_extends`，语义正确）。该约束由 `tools/verify-project.mjs` 静态护栏强制。
- **教训**：规则层 Node 测试跑在真实 JS 引擎上，测不出构建错译——凡新增涉及 Map/Set 的规则实现，必须在微信模拟器里过一遍行为回归。

## ADR-007：命令行类型检查是验证链必经一环 —— 编辑器编译不构成 tsc 闸门

- 状态：已确认（2026-09-03，SLICE_006 复盘实证）
- **背景**：连续数个「用错 Cocos API」的 bug（`EventTouch.preventSwallow` 是布尔属性却当方法调用、`Node.scheduleOnce` 不存在——它是 `Component` 的方法、`canPlace(state,def,x,y)` 被传成 5 参数导致合法格高亮从未生效、`Node.setActive`/`Label.let()` 凭印象使用）都有同一特征：**凭印象写引擎 API，且命令行验证链里没有类型检查**。Cocos 编辑器内部会按 `temp/tsconfig.cocos.json` 全量编译，但只有编辑器打开项目时才发生；CLI 构建/回归不经过它，而根 `tsconfig.json` 的 `files` 只含微信类型声明、不含业务代码——直接 `tsc` 根本不检查 `assets/scripts`。这些错误因此一路活到模拟器，有的还被触摸回调静默吞掉（高亮 bug 存在了两个切片未被发现）。
- **决定**：新增 `tsconfig.check.json`（include 业务代码、target/lib ES2020、对引擎 `.d.ts` 全量检查）与 `tools/typecheck.sh`（`temp/declarations` 未生成时跳过），接入 `npm run verify`：doctor → **typecheck** → node 测试 → 静态护栏。
- **理由**：类型错误在本机秒级报出，成本远低于模拟器回归；引擎 API 表面大、记忆不可靠，tsc 对着官方声明做校验正是「先查手册」原则（ADR-004/ADR-005）的自动化版本。SLICE_006 首次接入即报出 15 处问题，含 2 个潜伏运行时 bug（canPlace 参数、scheduleOnce）。
- **注意**：tsc 只查类型不查行为，微信构建错译（ADR-006）类问题仍需模拟器行为回归；两道闸门互补。

## ADR-008：全项目评审修订 —— 语义对齐与护栏补全

- 状态：已确认（2026-09-03，全项目评审发现）
- **背景**：对代码/文档/测试/工具链做了一次全面评审，发现多处「文档承诺与实际执行不符」和「实现与语义不符」：① `verify-project.mjs` 的核心边界断言只读 `prototype-state.ts` 一个探针文件，core 其他 8 个文件引入 `cc`/`wx` 均不会被拦（文档却宣称全层强制）；② 结局判定 `nextDay > FINAL_DAY_INDEX(9)` 使第 9 天返仓即触发结局，与「存活到第 10 天结束」语义不符（实际只玩 9 天）；③ 幸存者求救事件的「救助」实际效果是亏 1 药品、`survivors` 永远为空——EventOutcome 类型无法表达招募；④ damage 后果不置 `vehicleDamaged`、事件表无任何 damage 条目使防护/`protectionSensitive` 全是空转；⑤ 「重新开始」漏清 `trunk.v1`；⑥ driving/returning 相位存档恢复是半死状态。
- **决定**（本次一并落地，规则改动附测试）：
  - 三层边界静态护栏改为**全目录扫描**：core 全部文件断言 `from 'cc'`/`wx.`，presentation 全部文件断言 `wx.`（平台访问只走 platform 适配器）。
  - `advanceDay` 结局改为 `nextDay > GAME_DAYS`（玩满第 10 天）；守卫对 day==10 且 ending==null 的存档兜底补 `survived`（`SURVIVED_ENDING` 导出），杜绝永久卡死；`FINAL_DAY_INDEX` 删除。
  - EventOutcome 新增 `recruit` 后果（救助 → 幸存者加入 `state.survivors`，职业取自事件表）；`survivor_call` 救助选项改用之；`ambush` 反击选项 damage 化并真实置 `vehicleDamaged`（防护减免路径从此有真实触发者）。
  - 存档键位单一登记处：`core/scenario.ts` 导出 `ALL_SAVE_KEYS`，「重新开始」遍历清档（含 PrototypeScene 的 `trunk.v1`）。
  - driving/returning 相位载入时回退地图（油弹为已付成本，不二次结算）；`atNode` 重建面板不变。
  - `LOOT_DRAW_MAX` 6→5（互斥抽取上限即物品种类数，6 不可达）；`DANGER_STEP` 替换 advanceDay 里的硬编码 +1，删除无消费者的 `DAILY_FUEL_IDLE_COST`；`canAffordTrip` 的 range 恒真检查保留但显式注明占位语义；route 死三元化简；表现层两处 `as never` 收紧为 `isLootItemId` 守卫；`engines` 收紧 `>=22.18`（node 直跑 .ts 依赖 22.18+ 默认开启的 type stripping）。
- **教训**：静态护栏的断言范围必须与文档承诺一致——「查了一个文件」和「查了整层」在文档里写出来是一样的，只有故意注入违规才能发现差距；规则语义（玩几天、救助有没有用）要以玩家视角复述一遍再对照实现，光看测试绿不绿发现不了「实现得很自洽但语义错了」的问题。

## ADR-009：验证节奏分层 —— 小项目不做大项目的仪式

- 状态：已确认（2026-09-04，用户拍板；**唯一权威出处为 [VERIFY_CADENCE.md](VERIFY_CADENCE.md)**）
- **背景**：2026-09-02~04 实测三场长会话累计约 270M 输入 tokens（本地 rollout 逐调用账目），99.7% 在输入侧重发上下文，成本随调用数 O(N²) 滚雪球；其中大量消耗来自「每个切片都做模拟器全流程回归」的节奏。同时 ADR-008 证明 3000 行级项目一次会话即可完成全项目审阅并抓出六类问题。结论：逐切片全量回归是小项目套用大项目仪式，验证应按风险分层、集中在阶段末。
- **决定**：T0（`npm run verify`，本机零成本）任何改动全跑；T1 定向回归只在改动触及存档读写/行为分支时跑所涉模块；T2 冒烟用于纯表现层改动；T3 全量回归 + 全项目审阅只在阶段收官、构建管线/存档 schema/护栏自身改动、发版前触发。阶段末由 glm-5.3（架构师）审阅、glm-5.3-flash 顶层新会话执行回归（子代理无 computer-use 且继承会话模型；glm-5.3 无图像输入）。`.agents/skills/wasteland-depot-dev/SKILL.md` 旧规则「表现层改动必须构建 Web 验证」废止。
- **教训**：静态审阅抓不到构建错译（ADR-006 类），故 T1/T3 触发条件按**风险面**（改了什么）而非日历；全局风险（护栏/补丁/构建配置）爆炸半径是整个包，一行 diff 也触发 T3。

## ADR-010：游戏骨架切换 —— 十日单线模型退役，区域制长局模型定型

- 状态：已确认（2026-09-06，用户拍板，GDD 七轮对话收敛）
- **背景**：旧骨架（十日 × 六地点单线）在 SLICE_001~006 验证了货舱占格、横轴卷轴、事件结算等**手感资产**，但玩家视角「3 分钟看破全貌，无新鲜感」——缺进程感与揭示感。经对标《地下城堡》系列（1/2 代走格迷雾的肝度教训、3 代全砍失去灵魂、4 代回归+减负）与《月圆之夜》（小成本靠设计密度长留存的标杆），用户给出完整简化版设计，七轮细化后定型。
- **决定**（设计权威出处为 [GAME_SKELETON.md](GAME_SKELETON.md) 第二版）：
  - **探索形态**：平面区域地图（仓库一角、市中心中央）+ 横轴区域场景（连续 10 事件节点：搜刮/NPC 任务/必战怪物，顺序随机）；事件发生在目标区域内而非路途（地图实现成本与叙事都更干净）。
  - **主角人车合一**：开局三选一（注：后拍板为「多选一」，见 ADR-015），仅带一个区域掉落天赋；默认司机，占驾驶位不计人数与载客量；全员健康度 = 唯一生命系统，药品恢复，无装备栏、NPC 属性一致（人数=物资乘数与攻击乘数）（注：攻击乘数已废——乘数只作用于物资掉落、不进战斗，见 ADR-013/014；「健康度」术语已统一为「血量」，见 ADR-015）。
  - **单一攻击管道**：车载武器是唯一攻击来源，一条 9 级升级链（机枪→重机枪→火箭巢，工作台等级=升级门槛）；守家战复用同一管道，伤害方向为 怪物→载具耐久→仓库耐久→全员健康。
  - **守家波次**：每 N 天怪物攻家，战前二选一（出车迎/守工事）自动结算；波次明牌提前一天预告；防守失败=全员健康扣至 20/100 + 仓库随机丢 5~20 件物资（不直接死档）；波强度=危险度的实际结算效果（D5 落地），爬升封顶保休闲线。
  - **胜负**：胜利=修复市中心基站发出求救；失败=全员健康归零重开。长局，无天数硬上限。
  - **砍掉的旧设计**：十日时限、六地点单线、幸存者占货舱 2×2（改载客量制）、NPC 职业差异、枪械船票制（曾短暂提案）、农田/牲畜舍生产线（第五轮用户自砍）、路途损耗耐久（第七轮否决）。
  - **新增设计纪律**（GAME_SKELETON §14）：决策不超前于信息、合成 ≤1 跳、牌面即全部真相、单一攻击管道、新要素先挂现有五资源。（注：其中一条节奏类纪律已于 2026-09-07 由用户收回，不再作为设计约束，其余五条维持。）
- **理由**：用户的口味分析（地下城堡疲劳=迷雾下高频低密度决策；月圆之夜八年=关系发现式乐趣；roguelike 二选一=复杂决策切片化）指向「低频高权重、可预算、明牌」的设计取向，新模型每个系统都按此校准。
- **后果**：核心层 `GAME_DAYS`/结局判定/职业数据/事件表需参数化改造，存档 schema 升版本（首个改造切片处理）；六切片的手感资产（占格/卷轴/事件面板/五资源账目）全部复用，无沉没成本。数值项全部入 [PENDING_DECISIONS.md](PENDING_DECISIONS.md)（D2/D5/D6/D8/D9/D11~D16）。
- **教训**：旧骨架把「验证取舍手感的原型范围」当成了「游戏的完整形态」——原型验证完就该升级模型，而不是在明牌单线上继续堆排程感。

## ADR-011：战斗系统 v2 —— 自动结算退役，改为竖版定点实时射击

- 状态：已确认（2026-09-07，用户拍板，战斗设计三轮过夜迭代收敛）
- **背景**：ADR-010 定稿时战斗为「自动结算」。用户当晚复盘认为纯自动无操作参与感、可玩性打折，先试图改「人员装备+阵型」（推翻人不带装备底线），最终落点回到车载双武器——保住「人不带装备、攻击全在车上」两条底线，同时把参与感补回来。
- **决定**（设计权威出处 [GAME_SKELETON.md](GAME_SKELETON.md) §7/§10）：
  - **形态**：竖版定点实时射击（对标《向僵尸开炮》）。战车固定屏幕底部中央，不横移；怪物自上方刷出，**中间密、向两侧递减**。
  - **全手动**：机枪锥形射界、点按场景转向开火（射速高、穿透 1~2）；火箭筒从按钮**拖放**到目标点、范围伤害、装填长、单场 3~5 发（可升级威力/范围/上限）。不做自动发射模式（双模式=双倍成本且必有劣势边）。
  - **弹药经济——演出与结算分离**：战斗画面弹数不计账；机枪每场固定扣一次（随区域等级升高），火箭弹按发折算（1 发=200 弹药，出发整备时携带，未带则火箭筒不可用）。设计逻辑：机枪若按发计账，高射速下数值爆炸且「省弹=不打」自相矛盾；固定扣+等级阶梯把弹药做成「进入门槛+预算题」。参考锚点（用户给出）：5000 发级关卡对应火箭弹 1 发=1000 弹药；实装默认值收敛为 400/800/1600/3000/5000 阶梯与 1 发=200（弹药池与弹道画面的比例自洽留给切片调参）。
  - **战斗可选制**（初版为「必战+事务性回退」，2026-09-07 用户修订）：怪物关卡可战可绕，前置弹框明示扣弹与掉落；弹药不足选战按战败结算（D20），不回档——弹药不足的出路是绕行。设计动机：架构对弹药依赖偏弱，改可选制+高怪物掉落，把弹药流从「被动储备」引导为「积极开怪换收益」。
  - **守家战管道串联**：战车前多一道围墙（仓库耐久），伤害依次 仓库耐久→战车耐久→全员健康；探索战无围墙从战车起算。不做漏怪判定（少一层计算系统）；围墙修复成本=战车 0.5 倍。
  - **boss 战**：区域尾节点固定 N 局（默认 3），扣弹与掉落为同级 ×3。
- **理由**：用户设计直觉一以贯之——砍系统不砍参与（「少一层计算系统」）；演出不必忠实结算（「又不是战争模拟器，不天马行空就不成游戏」）。
- **后果**：战斗从事件结算升级为实时场景，工程量 +1~2 个切片；ADR-010 中「守家二选一」「伤害管道 怪物→载具→仓库→人」的表述由本 ADR 修正；PENDING 新增 D17（boss 战规则）。事件结算框架不废——非战斗事件仍走原管道。
- **教训**：纯自动结算与操作参与感是两个独立开关——为减负砍掉操作层，会连参与感一起砍掉。

## ADR-012：失败语义重定义 —— 车毁降级、主角机器人化、波次日历制

- 状态：已确认（2026-10-08，用户拍板，GDD 第十六轮收敛）
- **背景**：第十三~十五轮数值定稿（d9f8031）引入「战败 -50 耐久 + 车毁即败」后，全项目 GDD 审阅发现失败语义与伤害管道（车永远先于人掉光）冲突——「全员健康归零」这条主失败条件在战斗中实际不可达；同时波次触发口径（按行程 vs 按天数）、危险度封顶（§10 封顶承诺 vs D5 无封顶）两处文档打架，健康阶梯出现空档（≤50 与 >50 档数值相同）。
- **决定**（设计权威出处 [GAME_SKELETON.md](GAME_SKELETON.md) 第三版）：
  - **车毁降级**：战车耐久归零不再判负——战斗立即结束、无掉落、强制返程回仓库，修好再出发。战斗败北的「固定 -50」结算随之废除；弹药不足强开普通怪 = 进场实战白挨到车空（牌面即真相）。失败条件只剩一条：**全员濒死**。
  - **主角 = AI 机器人**：没有血量、不吃食物、不参与血量结算，只承战车耐久（人车合一的字面化）。开局自带 1 名 NPC，与招募 NPC 同一基类，属性仅 血量上限+当前血量 两字段。
  - **顺序扣血 + 濒死驻留**：车破后伤害按队伍顺序逐人扣 NPC 血量；归零=濒死（不死），永久驻留仓库直到拉出濒死线；濒死者照吃 2 食物/天、不计探索/攻击乘数。所有 NPC（含驻留者）同时濒死 = 游戏失败。
  - **守家战**：管道 围墙→战车→NPC 血量（顺序扣），围墙=战车耐久 200、修复成本 0.5 倍。**每 20 天固定一波**（第 20 天日结触发，取代「每 4 次行程」），强度逐波增强、无封顶——压力即策略源（用户定位：Roguelike+末日经营，不是星露谷），尺度=别逼玩家像计算机器。
  - **缺席惩罚**：波次日结时在途 = 掉围墙 + 五种普通资源全清；**区域地图、信号零件、修复进度、仓库/载具升级全部保留**——伤经济不毁存档。
  - **血量三档阶梯**：≤50 → 50%、>50 → 100%、>100 → 200%，作用于食物/材料/弹药/药品（燃油不参与）。（注：口径已由 2026-10-08 审阅修订为「逐人按各自血量定档、档位求和」，现行见 D6。）
  - **补剂改制**：3 药+2 食 → 恢复当前血量 +50，无限次使用，不再提升上限（上限恒 200）——「药当饭吃」：饥饿掉血（断粮每人每天 -10）可以用药补回，药品系主角由此成立。（注：本条已被 ADR-015 改为药神专有 + 双加提上限，现行见 D19。）
  - **多日探索补油**：再探一天 = 换子区域 + 追加耗油——堵住「按天计波后长行程白赚天数」的漏洞。
- **理由**：用户三句话定调——①「波次没有压力就没有策略性，这不是星露谷」；②「主角是 AI 机器人，人车合一」；③「缺席清物资但不该清区域地图，这是常识」。失败线收成一条（全员濒死）后，车、墙、人三层管道各自有了不判负的明确语义。
- **后果**：PENDING 的 D5/D6/D11/D14/D19/D20/D22/D25 标记已确认；D12 载具属性表定整数（200~350 耐久阶梯等）；D21 补饥饿结算数值（-10/天、1 药=20 血量）。ADR-010/011 中「全员健康归零」「防守失败不直接死档」「战败 -50」的旧表述由本 ADR 修正。实现侧：结局判定、血量结算、波次触发、存档 schema 待区域制改造切片一并处理。
- **教训**：往既有伤害管道上叠「即败」条件，先画一遍数值流向验证可达性——车先于人掉光的管道里，「人死」条件天然不可达；另外每一轮拍板后要跑一遍「新规则 × 全部旧章节」的交叉审阅，这轮的四组冲突全是十三~十五轮单点修改没同步邻居章节留下的。

## ADR-013：弹药制与怪物模型 —— 废除弹药门槛，改实时消耗 + 撞线自毁

- 状态：已确认（2026-10-08，用户拍板，GDD 第十七轮）
- **背景**：用户复盘认为战斗的弹药量限制的设计动机已不成立（ADR-011 原意图=把弹药做成「进入门槛+预算题」），指示若无必要原因即废除——「有多少都能打，无非是弹药耗尽的情况下用命抵扣、用载具耐久抵扣」，并提议怪物有生命值、冲到防线造成伤害。丧彪在「撞线自毁」与「怪物攻击力」两案中拍板自毁（用户授权：框架丧彪能定就定）。
- **决定**（设计权威出处 [GAME_SKELETON.md](GAME_SKELETON.md) §7/§9）：
  - **弹药实时消耗**：机枪按射速实时扣弹药、火箭弹每发实时扣弹药，演出弹数与账目一致（ADR-011 的「演出与结算分离」退役）。弹药量**不限制进入战斗、不锁武器**——打光就硬扛。
  - **弹尽结算**：怪物继续推进撞线，伤害沿既有管道（守家=围墙→车→人，探索=车→人）由战车耐久与 NPC 血量硬扛；扛到车空=强制返仓（D20），扛到全员濒死=失败。「用命抵扣、用耐久抵扣」即用户原话。
  - **怪物撞线自毁模型**：每只怪物仅 **生命值** 一个属性；被打死即消失，推进到防线自毁、**按剩余生命值等额扣损防线**——单只血薄撞线不致命，漏一小片就是几十点、漏满血大怪照样穿甲，输出即防御。**无攻击力属性、无近战驻留**——理由：攻击力=驻留反复攻击=需新建近战逻辑（攻击频率/目标选择），自毁是一次性数字，战前弹框可直接明示「撞线伤害 X/只」，牌面即真相、砍系统不砍参与。
  - **boss = ×3 大号**：同模型血厚、撞线按剩余生命 ×1 结算（生命 ×3 已体现体量，撞线不再叠加倍率——与普通怪同一公式）；原「固定 3 局」退役（实时战斗下单场即可）。**D22 boss 重罚（三项 -50）与终局 boss「弹药不足=game over」特例全部废除**——弹尽风险由管道自然结算，无需特殊规则。
- **理由**：门槛制是叠在天然压力（撞线伤害）之上的多余结算层；弹药的新压力语义=「持续战力储备」，打光是渐变代价而非二元门槛，玩家决策粒度更细（打多少、省多少、扛多少）。
- **后果**：PENDING D13 改实时消耗口径、D17/D20 定稿、D22 废除、新增 D26（怪物数值初版，后被第十八~二十轮修订）；D26 与武器伤害/掉落的对表配平留战斗切片。ADR-011 的「弹药经济——演出与结算分离」「弹药不足按战败结算」表述由本 ADR 修正；设计纪律 §14 第 4 条中「演出弹数与结算账目分离」删去。
- **教训**：「为什么当初这么设计」的答案会随系统其余部分的重构过期——每轮大改后该回头审视自己当初的配套理由是否还活着（本例：门槛制是给旧的固定扣弹制配套的，扣弹制死了它就没了存在依据）。
- **修订（2026-10-08 第十八~二十轮，用户三连拍）**：①撞线伤害从「按怪级固定值」改为**按剩余生命值等额扣损**（打掉的每发都在减伤，输出即防御——固定值制下打残的怪和满血怪一样疼，输出会「白打」）；②怪物从「少量厚血」反转为**血薄量大的潮水制**（对标 PvZ「一大波僵尸」/向僵尸开炮：单场几十到上百只、分 3~4 波涌入、一两枪一个）——爽感来自击杀频率；③**全表整数化**（用户原则：数值简单方便口算）——怪物 10/20/40、机枪 5/10/20 伤害/发、火箭弹 40/70/100（半径 100/150/200、100 弹药/发）；数值对表见 PENDING D13/D26。

## ADR-014：第二十一轮 GDD 审阅修订 —— 围墙升级/数值调参/字段清理

- 状态：已确认（2026-10-08，财哥拍板，丧彪执行文档修订）
- **背景**：第二十轮整数化后丧彪做全量 GDD 交叉审阅，抓出三类问题：①围墙修复比例 1:2 与「统一 1 材料=25 耐久」同段自相矛盾；②补剂配方（3药+2食=+50）被药品直吃（1药=+20）严格碾压、配方永远不会被使用；③D17 残留旧 boss 血量 150/450/1200 未对齐整数化表、载具「攻击」字段与已定的武器数值表重复、终局时序与资源占格规则两处空白。
- **决定**：
  - **围墙**：修复固定单价 **1 材料 = 25 耐久**（财哥：围墙设计用途=守家加厚血量，修缮便宜是次要，不走比例计算）（注：修复单价已由 ADR-017 改为 1 材料 = 10 耐久，现行见 D12/D14）；围墙新增**第三维升级科技树**（200/300/400，成本见 D9）——解决围墙中后期恒 200 薄如纸的问题。（注：档位口径 2026-10-09 更正为初始 200 + 升级 300/400/500，现行见 D9/D14。）
  - **补剂**：配方改 **2 药品 → 1 份**（不再含食物）；药品直吃刷到 100 前最便宜，突破 100 后补剂是冲 200 上限的高效通道——给药品越过直吃边际的主动出口（药神系特长同步为 2→1）。
  - **boss 血量对齐**：D17 改为 ×3 = 30/60/120（基于整数化后的 10/20/40）。
  - **载具「攻击」字段**：**不设**（财哥拍板）——全游戏**只有两个攻击力数值：载具机枪每发伤害、载具火箭弹每发伤害**（见 D13），**不再做别的乘数计算**：无载具攻击字段、无血量阶梯乘数、无人员乘数。血量阶梯与人数乘数只作用于探索物资掉落，不进战斗。
  - **火箭弹数值上调**：40/70/100（原 20/40/60 对满血小怪伤害溢出、对大怪又打不死，切片配平时重估）。
  - **待审提案 → 已拍板**：D27 终局时序（仓库执行修复、修复当刻触发终局波、在途按缺席结算但抵抗军照常抵达）、D28 资源占格（1 格=10 单位、同资源可堆叠）——财哥 2026-10-08 审阅通过。（注：其中「在途」分支 2026-10-09 已删，现行见 D27。）
- **修订（2026-10-08 当日，财哥对载具攻击口径的两轮更正）**：① 上一版把「攻击」字段整条删除（判断为旧模型残留）——财哥指正载具攻击力是固定值；② 随即财哥再澄清**根本没有载具攻击这个维度**——武器伤害即载具攻击，全游戏攻击力只有机枪/火箭弹两个数值，无任何乘数。两版修正同步厘清乘数归属：血量阶梯与乘员人数乘数**只作用于探索物资掉落，不进战斗**。教训：**删字段前先问一句「这是冗余还是定义缺失」**——本例「语义未定义」先被误判成「冗余」，后又被过度补全成「固定值字段」；财哥的口径始终是「砍到不能再砍」，乘数层数要按玩家口算负担来约束。
- **后果**：GAME_SKELETON §4/§6/§7/§8/§9/§10/§11、PENDING D9/D12/D13/D14/D16/D17/D19/D21 + 新增 D27/D28、ADR-013 正文回改。实现侧：围墙升级、补剂配方、火箭弹数值随对应切片落 `constants.ts`。
- **教训**：GDD 多轮增量后「旧模型残留」是系统性风险——每轮拍板后要做「新规则 × 全部旧章节」交叉审阅（ADR-012 教训的再次验证）；文档里同一事物（AI 机器人主角）反复以不同措辞重述也是冗余源，表述要收敛。

## ADR-015：补剂专有化与 GDD 单一权威出处收敛

- 状态：已确认（2026-10-08，财哥拍板，丧彪执行文档修订）
- **背景**：第二十一轮落库后丧彪复审，确认交叉重复是错漏温床（ADR-014 教训的实证）：「唯二攻击数值」写了 6 处、boss 撞线模型 4 处、围墙数值 5 处，同轮修订漏改邻居即成硬冲突（本轮抓出 §2「攻击乘数」、§4「两维升级」两处残留）。同时补剂经济存疑：2 药=+50（每药 25 血）严格优于直吃 1 药=+20 且无限次使用，原表述「直吃刷到 100 前成本最低」不成立。
- **决定**：
  - **补剂专有化与双加效果（财哥口径）**：人类补完の剂为**药神流专有配方**——仅「我就是药神」可制作。效果**双加：血量上限 +50、当前血量 +50**，是全游戏**唯一提升血量上限的手段**（药品直吃只回血不提上限）。设计闭环：探索高档门槛是当前血量 >100，基础上限 100 靠普通手段无法越过，必须补剂推上限；**200 硬顶**防药神流无限刷医院区不出去——保住「各流派在优势区刷够、按需去别区换物资」的跨区域循环（硬顶本身可有可无，保留是为了这条循环纪律）。
  - **术语统一（财哥定）**：「健康度」全文改为**「血量」**——同一属性，游戏里叫血量更通用。
  - **文档收敛规则（治理约定，自此执行）**：①机制叙述唯一住 GAME_SKELETON；②数值唯一住 PENDING D#；③GAME_SKELETON 正文内嵌数值改「见 D#」指针（2026-10-08 补充：波次间隔、节点构成、倍率、门槛值等机制骨架常数允许复述；成表的可调数值仍一律指针化）；④ADR 只记「为什么」，不复制现行数值——旧 ADR 内的历史数值不改，由后续 ADR 标注 superseded；⑤PENDING「已拍板记录」节删除（与 ADR 重复，拍板记录以 ADR 为权威）。
  - **错漏修正（丧彪按规则执行）**：§2 攻击乘数残留、§4 仓库两维→三维、boss 撞线 ×1 口径对齐、D17「固定 N 局」残留、「局长」笔误、D11/D24 日期勘误（10-07→09-07）、D12 防护补 0% 基础档、README/PENDING 版本引用更新至第三版。
- **理由**：财哥审阅确认「一个事情几个文档各写一点」属实且是错漏主因，同意丧彪提议的收敛规则并授权执行；补剂经济疑问由「专有配方 + 双加效果」定性化解——严格优于直吃不再是漏洞，而是路线优势本身（直吃回血、补剂推上限，职能不同）。
- **后果**：GAME_SKELETON/PENDING/DECISIONS/README 四文档按规则修订；后续每轮 GDD 增量按本规则落库，交叉审阅仍执行（ADR-012/014 教训）但冗余面大幅缩小。ADR-012「补剂 3 药+2 食、只回血不提上限」与 ADR-013 后果段 D26 旧初值（50/150/400、10/25/60）自此视为 superseded，现行值以 PENDING 为准。
- **教训**：审阅者自己也会误报——本轮曾把「ADR-013 火箭弹 20/40/60」列为错漏，git 取证发现 c5e0075 已改为 40/70/100；交叉审阅的结论在下笔修订前应逐条对照当前文件核实。另：ADR-014 曾把补剂定性为「恢复当前健康 +50」的纯回复手段并自洽论证——对已拍板机制的理解要以设计者原意为准，不要用「能让现有文档自洽」的最小改动代替问清语义。

## ADR-016：第二十三轮 GDD 审阅修订 —— 收益乘数口径与交叉残留清理

- 状态：已确认（2026-10-08 首轮，2026-10-09 两轮追认定案，财哥拍板）
- **背景**：外部审阅（k2.8 / glm-5.3）收尾后，丧彪对主文档做全量交叉复审，收出 13 项：多数属「同一事实多处表述」的机械残留（与 ADR-015 病因同源），少数为口径空白（收益乘数算法、围墙档数、终局在途分支、无归口数值）。

  - **数值落点修正**：玩法数值落点为 `constants.ts` + `game.ts` + `loot.ts` 三处（原「唯一 constants.ts」表述遗漏 loot.ts）；ARCHITECTURE 与项目 skill 同步。

- **追认定案（2026-10-09 财哥拍板）**：① 围墙升级 3 档耐久 **300/400/500**（初始 200，成本 40/80/120 不变；ADR-011/012/014 中围墙耐久与修复单价的旧表述——含「修复成本=战车 0.5 倍」「200/300/400」——一并 superseded，现行见 D9/D14）；② D27 删「在途=按缺席结算」死分支——语义不可达（修复必在仓库执行、当刻触发），终局只留「人在仓库正常开打，扛过去即胜利」；③ 车辆修复与围墙统一口径 **1 材料 = 25 耐久**（注：修复单价已由 ADR-017 改为 1 材料 = 10 耐久，现行见 D12/D14）；④ D26 守家量级改潮水制口径（40~80 只起步、逐波升至百级，强度曲线归 D5）。

- **待拍板（2026-10-09 更新）**：~~**燃油去留（产品级，财哥拍）**~~ → 已由⑤定案（保油+保底）。区域制探索油耗（按天扣除口径）已随⑤落 D29，不再悬置。
- **理由**：三项口径由财哥当场拍板（乘数逐人累加、裸值 +1、格数显示自由）；其余为复审确认的机械修正，不动机制。治理例外让「核心常数复述」有明文依据，避免每次复审重复计为违规。
- **后果**：GAME_SKELETON / PENDING_DECISIONS / README / ARCHITECTURE / DECISIONS / INVENTORY_DESIGN 与项目 skill 按规则修订；首轮四项遗留与第二轮燃油/耐久口径均已定案落库（油耗数值见 D29）。
- **教训**：机械残留的分布规律再次验证——同一事实复述 N 处，改一处必留 N-1 处；收敛规则见效，但存量历史复述仍需逐轮清扫。

## ADR-017：第二十四轮 GDD 审阅修订 —— 砍工作台/图纸制作玩法，科技树重构，信号零件直掉

- 状态：已确认（2026-10-09，财哥拍板，丧彪执行文档修订）
- **背景**：第二十三轮收口后丧彪再审，抓出 A1（§10 漏怪残留）/A2（ADR-010 主角口径未标 superseded）/A3（工作台机制无权威出处）+ B1（储物格无每格上限）/B2（零件归属不清）/B3（天赋 ×2 口径混乱）。财哥逐条拍板，改动面大（涉及 GAME_SKELETON 12 节、PENDING 10 个 D#、ARCHITECTURE、README），遂立本 ADR 一次性落库。
- **决定**（设计权威出处 [GAME_SKELETON.md](GAME_SKELETON.md) 第四版）：
  - **A1/A2 机械修正（财哥授权丧彪直接改）**：§10 删「不做漏怪判定——」七字（撞线自毁制下无可砍判定）；ADR-010 主角条加三行 superseded 注记（多选一替三选一、攻击乘数已废、健康度→血量）。
  - **砍工作台设施（财哥拍板）**：工作台四个用法（武器升级门槛、补剂合成、基站设备合成、仓库升级维度）全部砍除。仓库升级维度从 3 改为 2（储量、围墙）。补剂合成入口改**仓库药品栏**（点开药品 → 选「使用」或「合成」）。
  - **砍图纸物品/制作玩法（财哥拍板）**：图纸双通道、工作台配方、图纸物品清单全部砍除。只保留**区域地图**（解锁中/深层区域，NPC 任务直接给目标子区域地图如「加油站中区地图」，探索掉落同，无碎片攒集）。原「零件→合成设备→修复」链作废。
  - **信号零件直掉（财哥拍板）**：基站收集品从「图纸+设备」简化为**信号零件 A/B/C/D** 四件直掉，财哥选定丧彪提案命名——**信号发射器 A / 功率放大器 B / 稳压电源 C / 天线阵列 D**（废土捡破烂凑电台的代入感，比「图纸+合成」更朴素）。凑齐 4 件即自动修复基站，无合成步骤，不去市中心现场，当刻触发终局波（D27 同步简化）。
  - **科技树重构（财哥拍板）**：围墙/载具耐久/武器三线并入**统一科技树**（无前置依赖，材料够就能升——武器升级材料需求量大本身就是门槛，财哥口径）。储物量/载客量**不走科技树**——在载具面板用 **+ 号按钮**单独升（点击显示材料需求，确认即 +1 格 / +1 座位）。**防护属性已砍除**（财哥确认：现无防护这个属性）。
  - **修复单价调整（财哥拍板）**：1 材料 = 25 耐久 → **1 材料 = 10 耐久**（D12/D14 同步）。材料格上限 50 → **20**（D30）。
  - **物资流天赋改口径（财哥拍板）**：从「工厂区材料 ×2」改为**「探索掉落系数 ×2」**（全资源），与弹药流「战斗掉落 ×2」构成场景对。食物流/药品流无区域 ×2（优势来源=人口/上限，见 D11）。
  - **储物格每格数量上限（财哥拍板，丧彪设计数值）**：食物 50 / 材料 50 / 药品 20 / 弹药 100 / 燃油 20（单位/格），同资源可堆叠至该上限（D28/D30）。（注：材料上限已由财哥同日从 20 上调为 50——武器升级最贵 180 材料 ≈ 4 格，储物格要跟。）
- **理由**：
  - **工作台作用不大**：四个用法砍完四个，补剂改药品栏按钮更顺（药神流仓库操作少一步），基站改直掉少一整层合成链复杂度。
  - **图纸物品/制作玩法「先砍掉」**：财哥明确「先不要这个玩法」，保留区域地图解锁子区域（揭示感是长线新鲜感来源）。
  - **信号零件直掉**：废土捡破烂凑电台的代入感，比「图纸+合成」更朴素。
  - **科技树重构**：耐久是数值强化走等级直观；储物/载客是容量扩张走 + 号按钮即时反馈，突出「+1 座位=多一个乘数档」的质变。防护属性砍除——少了减伤维度，战车承伤更直白，管道更清晰。
  - **修复单价 25→10**：修车/修墙变贵，材料压力回升（修满 300 耐久车=30 材料，原来 12）；材料格上限 20 对齐（1 格=200 耐久储备）。
  - **物资流改探索 ×2**：跟弹药流战斗 ×2 构成决策对——一个管探索收益、一个管战斗收益，流派差异更鲜明。
- **后果**：GAME_SKELETON（12 节）、PENDING（D3/D9/D11/D12/D13/D14/D15/D18/D19/D24/D27/D28 + 新增 D30）、DECISIONS（本 ADR）、ARCHITECTURE、README 五文档同步修订。ADR-011/012/014/016 中涉及工作台、图纸制作、修复单价 25、储物格 1 格=10 单位的旧表述由本 ADR 标注 superseded 或同步修正。实现侧：工作台/图纸物品/零件合成相关代码与数据随区域制改造切片一并清理。
- **教训**：砍系统比加系统更难——每砍一个，要跑一遍「被砍系统 × 全部旧章节」交叉审阅，确认没有半句残留（本轮 GAME_SKELETON 12 节、PENDING 10 个 D# 全扫一遍才落笔）。另：财哥对「先砍掉不要这个玩法」的直觉非常准——图纸物品/制作玩法在 GDD 阶段就露出「复杂度大于丰富度」的苗头，早砍早轻松。

## ADR-018：第二十五轮 GDD 审阅修订 —— 零件改任务专属、节点固定构成、四流派天赋重定

- 状态：已确认（2026-10-09，财哥拍板，丧彪执行文档修订）
- **背景**：第二十四轮（ADR-017）落库后丧彪再审，收出 6 处机械残留 + 4 处口径疑点；财哥逐条回复，其中 7/8/9 三项当场拍板改设计，第 6 项（首波起算日）暂未定口径、第 10 项（软结局）丧彪提案待审。
- **决定**（设计权威出处 [GAME_SKELETON.md](GAME_SKELETON.md) 第五版）：
  - **信号零件改任务专属（财哥定）**：零件 A/B/C/D **不走探索/战斗掉落**（避免设计掉落概率），**唯一来源 = 深层（三级）子区域 NPC 任务奖励**；浅/中层任务给目标子区域地图。零件仍是关键道具单列、不占格，凑齐 4 件自动修复基站（D27 不变）。D15 由「三通道直掉」改口径。
  - **节点构成固定化（财哥定「探索:战斗 = 2:1」+ 任务固定刷出，丧彪补细节）**：单区域 10 节点 = **5 搜刮 + 2 随机事件 + 2 怪物关卡 + boss 收口**（非战斗 : 战斗 ≈ 2:1，顺序随机）；NPC 任务不占节点池，按**全局累计事件节点数**保底刷出——第 10/15/20 个必出、此后每 5 个一次，顶替原节点、撞 boss 位顺延（D8/D24）。解决旧构成「余量随机事件仅 1~3 位、喂不饱文案池」的算术问题。
  - **四流派天赋重定（财哥定，自判前版设计有误）**：食物流 = **食物掉落 ×2（探索+战斗）+ 所有 NPC 均可用食物招募**（不限对应资源）；物资流 = **物资掉落 ×2**；药品流 = **专有补剂配方**（人类补完の剂）；弹药流 = **战斗事件物品掉落 ×2**（天赋）+ 火箭弹单场上限 +1（身份特长）。食物流身份特长改为「全员食物招募」，原「招募 -25%」退役。ADR-016 首轮「弹药流=战斗掉落 ×2（弹药）」与第二十四轮「物资流=探索掉落 ×2、食物/药品无 ×2」的口径由本 ADR 修正。
  - **药品数值下调（财哥定）**：药品直吃 **1 药 = 20 血量 → 10 血量**（1 药作用过于巨大）；补剂配方 **2 药 → 5 药**。D19/D21/D30 依据同步（1 格药品 = 200 血）。
  - **机械残留清理（丧彪直接改）**：D3/INVENTORY_DESIGN「12→21 格」旧四档表残留 → 12→18（对齐 D12 三档）；D9 标题「储量/工作台/围墙」→「储量/围墙」；§8「食物 ×2」天赋残留与开篇旧区域掉落天赋描述 → 新四流派口径；PENDING 文末「ADR-010~016」→ ~018；§5/§11/§4 药品与零件交叉引用同步。
- **理由**：零件走任务不走掉落——省掉掉落概率设计，且「深层交朋友换零件」比「随机捡到终局道具」叙事更实；节点固定构成——2:1 比例是财哥给定的节奏锚，固定 2 个随机事件位让 20~30 文案池有稳定曝光；四天赋各管一块（食物=人口、物资=经济、药品=上限、弹药=火力）对称成立；药品降效——补剂（5 药=上限+50+当前+50）与直吃（1 药=10 血）的职能差拉大，药品「攒着合成 vs 直接吃」的取舍更清晰。
- **后果**：GAME_SKELETON 第五版、PENDING（D8/D11/D15/D19/D21/D24/D30/D3/D9）、INVENTORY_DESIGN、README 同步修订。ADR-016/017 中「三通道直掉」「弹药流（弹药）」「补剂 2 药」「1 药=20 血」「食物流无 ×2」的旧表述由本 ADR 修正。
- **教训**：流派天赋这类「一改全改」的口径，权威表（D11 主角清单）之外每处叙述复述都是雷——本轮「食物 ×2」残留正是第二十四轮改口径时漏刷的邻居；掉落概率类设计能躲则躲，任务保底制（第 10/15/20 个节点必出）是零概率设计的替代范式。

- 状态：已确认（2026-10-09，财哥拍板，丧彪执行文档修订）

## ADR-020：第二十七轮 GDD 审阅修订 —— 区域清单定案（D2）、层深口径全局统一

- 状态：已确认（2026-10-09，财哥定方向（12 地点素材 + 「主物资产地三层、综合产地一二处、太多反而不好」），丧彪收敛清单并执行文档修订）

- **决定**（设计权威出处 [GAME_SKELETON.md](GAME_SKELETON.md) 第六版·§9 区域清单表）：
  - **6 区域 + 市中心**：郊外农场（食物，唯一完整三层：农场/牧场/食品厂）、加油站（燃油，两层：加油站/炼油厂）、医院（药品，两层：医院/制药厂）、军营（弹药，两层：军火库/军工厂）、工业区（材料，两层：工厂/物流仓库）、老城（综合，广场/购物中心，不分层、均浅层难度、开局开放无解锁）。财哥给的地点**全部用上、不再新增**。
  - **层深口径（全局适用，随本 ADR 定案）**：浅层 = 各区第一层；中层 = 仅郊外农场有（牧场）；**深层 = 各区最深层**（农场第三层食品厂、其余四区第二层）。零件来源（D15）、任务分层（D24）、油耗（D29）中的层深均按此口径——「深层任务出零件」不因四区无第三层而堵死。
  - **油耗换算层深口径**：原「一级免油、二级 1 油、三级 2 油」改为「浅层免油、中层 1 油、深层 2 油」（数值不变，口径换算；D29 同步）。
  - **解锁粒度 = 分层制**：资源区浅层开局开放（与免油保底呼应——开局 5 个免费浅层 + 老城可选），更深层（农场中层/深层、四区深层）需地图解锁。
- **理由**：五资源各一个专项区保证「缺什么去哪」的跨区域循环（财哥口味：硬约束而非属性堆叠）；食物是硬通货（招募券，§8），给唯一完整三层；老城综合区不设解锁，开局攒情报起步；四区两层是「地点素材用尽」的自然收敛——不硬凑第三层地点，用层深口径吸收差异（四区「第二层即深层」），比给每区凑满三层更贴合「不用那么复杂」的要求。
- **后果**：GAME_SKELETON（版次行升第六版、§4 边界表、§9 区域清单表+层深口径+解锁分层制+例句统一）、PENDING（D2 落库✅、D15/D24/D29 口径对齐、文末 ADR 引用 ~018→~020）、README 同步修订。旧「8~10 个区域」「一级/二级/三级子区域」「加油站中区」等表述由本 ADR 修正。
- **教训**：结构变化必催生新口径词——「四区无第三层」迫使「深层=各区最深层」的重新定义，而这个新口径又要回灌零件/任务/油耗三处旧条款。结构性改动后，先找**受牵动的全局名词**，再 grep 它的所有住处。

## ADR-021：第二十八轮 GDD 审阅修订 —— 区域清单简化定稿（D2）、层术语定为外围/内部/核心

- 状态：已确认（2026-10-09，财哥拍板，丧彪执行文档修订）
- **背景**：ADR-020 定案的区域清单（6 区域、四区两层、层深口径「深层=各区最深层」）落库当日，财哥从地图制作与 UI 角度重新简化：每区都做三层、层名统一，地图只做一套、选择交互用三个按钮。

- **后果**：GAME_SKELETON（版次行升第七版、§4 边界表、§9 区域清单表+三按钮交互+解锁+油耗+例句全部换外围/内部/核心口径）、PENDING（D2 重写、D8/D15/D24/D25/D27/D29/D30 术语对齐）、README 同步修订。ADR-020 的区域清单（郊外农场/加油站/医院/军营/工业区/老城、四区两层、浅/中/深层口径）由本 ADR 修正。

## ADR-022：第三十轮 GDD 重建 —— boss 掉地图/零件、任务系统标准化、探索日换算定案、骨架文档减重重写

- **背景**：第二十九轮五文档交叉复审收出 16 项（硬伤 4 + 缺口 6 + 机械 6），财哥逐条批复后指出根因：历轮「点名式」修订从未做过全局重排，矛盾必然累积；且骨架文档历史包袱重（版次注记、多处复述、成表数值内嵌），「每改一处漏一处」结构性无解。财哥授权**从零重写**：以 ADR-001~021 + 本轮批复为唯一真相源，旧文只作对照。
- **决定**（设计权威出处 [GAME_SKELETON.md](GAME_SKELETON.md) 第八版——全量重写）：
  - **boss 定案（财哥批 1）**：每区每层各一个 boss（全图 6×3=18 个），模型仍为撞线自毁大号（D17）。**地图与零件的来源整体从 NPC 任务挪到 boss**：外围 boss 掉深一层地图（内部地图）、内部 boss 掉核心地图——地图不再从 NPC 得、不再从探索掉落（原双通道取消，单一来源牌面即真相）；核心 boss 中 4 个各绑一件信号零件（丧彪定绑定：军工厂=信号发射器、工业园=功率放大器、制药厂=稳压电源、购物中心=天线阵列），食品厂/炼油厂两个核心 boss 无特殊掉落（财哥批 1 原文「其余掉空」）。**boss 只刷一次**：死后该层可再探但 boss 不再刷新（第 10 节点回填普通节点）。NPC 刷出沿用全局保底计数制（D24），保底节点不顶替 boss 位。

  - **文档减重（财哥定）**：骨架文档去版本史（历史只住 DECISIONS）、一机制一处定义（他处只「见 §x」）、已定死的小数值内联、术语残留（深区/情报/背包系统/修复进度）全清。
