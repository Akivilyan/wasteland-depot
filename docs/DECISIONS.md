# 已确认的项目决策

完整玩法范围、核心循环和待确认项见 [GAME_SKELETON.md](GAME_SKELETON.md)。本文只保留实施时必须遵守的产品与技术边界。

## 产品范围

- 首发平台是微信小游戏，PC 版延后。
- 第一版是一辆车、一个仓库和一小片地图构成的微型生存循环。
- 核心乐趣是有限载重下的取舍，不是复杂战斗或内容堆量。
- 首版保持纯 2D、竖屏、单机，不使用物理引擎和骨骼动画。
- 保留 Cocos `Animation` 与 `Tween`，用于按钮反馈、物品移动、格子高亮和容量告警等轻量动画。
- Spine、DragonBones、Box2D 等重型模块保持关闭；只有实际玩法和资源格式需要时才单独评估引入。

## 代码边界

```text
纯 TypeScript 游戏规则
        ↓
Cocos 表现与交互
        ↓
微信平台适配
```

规则层不能依赖 Cocos 或微信 API。微信存储、广告、登录、分享和生命周期只能通过平台适配器进入游戏。

## 广告底线

- 不放横幅、开屏和强制插屏广告。
- 只允许玩家主动触发的低频激励广告。
- 拒绝或加载失败不得阻断正常流程。
- 不故意制造痛苦，再出售痛苦的解药。

## 复用与不重复造轮子

开发新功能前，先确认官方/Cocos/微信是否已提供能力，**直接拿来用**，不要从头重写。以下清单是硬约束：

### 直接用官方/Cocos 提供的能力（不自己实现）

| 能力 | 来源 | 说明 |
| --- | --- | --- |
| 本地存档 | `wx.setStorageSync` / `localStorage` | 已有 `platform/storage.ts` 适配层 |
| 激励视频广告 | `wx.createRewardedVideoAd` | 只做适配层，不重写广告 SDK |
| 分享 | `wx.shareAppMessage` | 只做适配层 |
| 登录 | 微信登录 | 只做适配层 |
| 排行榜/关系链 | 微信开放数据域（OpenDataContext） | 只做适配层 |
| UI 列表/滚动/布局 | Cocos `Layout`/`ScrollView`/`Button`/`ProgressBar` | 物品列表、背包网格用官方组件 |
| 动画 | Cocos `Tween`/`Animation` | 按钮反馈、物品移动、格子高亮 |
| 触摸/拖拽输入 | Cocos 触摸事件 | 命中检测用官方事件，不重写输入层 |

### 必须自己实现的（官方确认没有）

- 背包/货舱的**占格、堆叠、拖拽规则语义**（Cocos 只提供列表生成示例，无现成背包组件）
- 十日核心循环、事件系统、地点/资源/职业数值与结算（纯 TypeScript 规则层）
- 可种子随机源（`rng.ts`，Cocos/微信不提供确定性随机）

### 判断流程

1. 需要某能力 → 查官方文档确认是否已提供（Cocos 手册 / 微信小游戏文档）。
2. 已提供 → 用官方能力，只写适配层。
3. 未提供 → 才写规则层实现，并确认它不依赖 `cc`/`wx`（保持可测）。
4. 拿不准 → 先记录到待办，不在不确定时从头实现。

> 当前阶段 1 只实现了「必须自己实现」的那部分；「直接用官方」的部分等阶段 2（表现层）才真正接入。

## 引擎与运行时（2026-09-02 定）

### 微信新运行时兼容（对照实验结论）

- 2026-09-02 起微信开发者工具模拟器运行时更新（灰度 3.17.1 / 新 3.17.2 构建）：不再预置 `window`/`global`/`requestAnimationFrame`，`GameGlobal` 上部分属性 getter-only。Cocos 3.8.8 生成的小游戏模板硬依赖这些全局，启动链逐层崩溃白屏。配置文件（project.config.json / game.json / libVersion / enhance）差异均非原因，**纯代码依赖问题，改配置修不了**。
- 对照实验：开发者工具原生"小游戏+纯gl模式"模板在同一模拟器 0 错误正常运行；Cocos 产物必白屏。社区普遍反馈过"新版运行时 window 不再注入"，微信与 Cocos 均无官方公告/适配。
- 治理：`tools/patch-wechat-deprecated.mjs` 七个幂等补丁随 `npm run build:wechat` 自动执行（废弃 API shim、global/window 别名、DPR 容错、first-screen window/rAF 兜底、adapter 双分支守卫、DOMParser 暴露 globalThis）。Cocos 官方适配后可移除。
- 开发期建议：开发者工具 设置→本地设置 锁定调试基础库版本，避免灰度运行时反复横跳。

### 引擎选型（复评结论）

- **留在 Cocos 2D**。游戏真实形态（横轴旅途+场景变化，归家异途变种）正是 2D 引擎价值区；"原生 canvas 更好"的判断只在纯静态 UI 假设下成立，已推翻。
- 备选：微信原生（规则层零成本可迁，引擎彻底摆烂时启用）。排除：团结引擎（3D/重度方案，C# 重写成本不值）。
- 教训记录：评估技术方案要以完整游戏形态为准，不能用当前已实现切片当依据。

## 表现层方向（2026-09-02 定）

旅途表现采用**"地图骨架+卷轴演出"折中**：

- 2D 地图做策略层：选路线/节点、开迷雾、节点状态（危险/已搜/营地）。
- 点出发切横轴行车卷轴做表现层：车移动、背景滚动、随里程触发节点事件。
- 到节点弹出事件/搜集/货舱界面（复用现有 UI 风格）。
- 首版只做一条路线 + 3~5 个节点验证手感；行车段横轴素材日后按节点对复用，不白做。
- 对标体验：归家异途（Home Behind）——路上横卷、地图/营地静态界面。用户确认此方案（2026-09-02）。

## 工作方式（2026-09-02 补充，用户反馈）

- 环境/工具链类异常（非自己代码逻辑错误）：**先联网检索已知问题**（`arkcli +chat --tools web_search`），确认是否社区普遍现象/有无官方公告，再决定跟官方方案还是自己兜底。不要顺着调用栈埋头深挖。
- 做兼容性对照实验时用官方向导/官方模板新建项目，不手工拼 project.config.json（会被 GUI 覆盖模式字段）。
